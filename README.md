# Emergency Response Management System — Erode District (Prototype)

A static, no-build, no-server web app built around the Erode District dataset:
login + signup, an administrator role, a theme switch, and a real-coordinate
district map, styled to look like a formal government emergency-services
portal.

```
sudar-dispatch/
├── data/
│   └── sudar-data.json       Clean JSON version of the dataset
├── web/
│   ├── login.html            Sign in / create account
│   ├── dashboard.html        Main console (protected — redirects to login.html if not signed in)
│   ├── backend.html          Separate option: same console driven by the Java program + MySQL (needs the Java API running)
│   ├── css/styles.css        Government light/dark theme tokens + all styling
│   └── js/
│       ├── data.js           window-global SUDAR_DATA (same content as data/sudar-data.json)
│       ├── auth.js           Client-side demo auth (see disclaimer below)
│       ├── map.js            Renders the district map from real x/y coordinates
│       ├── dashboard.js      Wires session, theme, tables, map, admin controls
│       └── backend.js        Java + MySQL page (talks to the Java REST API)
├── database/
│   ├── schema.sql            MySQL tables (locations, roads, units, incidents, incident_needs, assignments, dispatch_log)
│   └── seed.sql              INSERT statements for the 114 places, 186 roads, 42 units, 4 incidents
├── src/sudar/                Java program (OOP + data structures + Dijkstra + JDBC) -- see below
├── lib/                      put mysql-connector-j-*.jar here (only needed for MySQL)
├── config.properties         MySQL host / user / password and API port
└── run.bat / run.sh          compile and start the Java program
```

## Running it

No build step, no server. Just open:

```
web/login.html
```

directly in a browser (double-click it, or File → Open). Everything — login,
the dataset, the map — runs from local files.

## Signing in

| Username | Password    | Role           |
|----------|-------------|----------------|
| `admin`  | `Admin@123` | ADMINISTRATOR  |

Or click **Create an account** to register a new operator (role `OPERATOR`).
New accounts always get the operator role — only the seeded `admin` account
is an administrator, and only administrators see the **Administrator
Controls** panel (road open/close toggles) at the bottom of the dashboard.

**This is a client-side demo, not a real authentication system.** Accounts
and passwords are stored in the browser's `localStorage` in plain text —
fine for a prototype, but it must never be used to protect real data. A
production version would authenticate against a server with hashed
passwords.

## The map

`map.js` plots every location at the exact `x`/`y` coordinates given in the
dataset — it's a real positioned district layout, not an auto-generated
force-directed graph. Roads are colored by their `traffic` multiplier
(green/amber/red) and a `blocked: true` road is drawn dashed with a red ✕
badge. Each location marker uses a distinct glyph for its `type`
(▲ station, + hospital, ◆ market, ■ industrial, ● school/residential,
• junction), plus a small red count-badge if it currently has an incident.
A compass rose and a scale bar (derived from one road's real km vs. its
pixel length) are included for map-like authenticity.

## Theme

The dropdown in the header switches between **Government Light** and
**Government Dark** — both formal/official palettes (navy, saffron, green
accents, no neon). The choice is saved in `localStorage` and carries across
the login and dashboard pages.

## Admin controls

Signed in as `admin`, the **Administrator Controls** panel lists every road
with an Open/Close button. Toggling one instantly updates the map (the road
redraws dashed-red when closed) and the KPI "Roads Open / Closed" count.
This only changes the in-browser copy of the data for this session — it
does not write back to `data/sudar-data.json`.

## Dataset

`data/sudar-data.json` (and its JS-global twin `web/js/data.js`) is generated by
`python3 tools/build_data.py`. It contains: `town`, `locations` (**114** across all 10
taluks of Erode District, with lat/lon, taluk, type and map x/y), `roads` (**186**, with `km`,
`traffic`, `blocked`; the original 14 are kept and the network is guaranteed connected),
`units` (**42**, across FIRE/POLICE/AMBULANCE -- one fire+police pair per station, one
ambulance per hospital), `incidents`
(4 seeded + any you report live, each with a `needs` list — i.e. incidents can require more than one unit
type, e.g. FIRE *and* AMBULANCE), `assignments` (unit → incident routes with
distance/time), a `log` of dispatch events, and `averageResponseMinutes`.

## What's new in v2

- **114 places / 186 roads / 42 units** (your original 12 places, 14 roads, 6 units and 4 incidents are kept).
- **Live dispatch engine** (`web/js/dispatch.js`): Dijkstra routing + busy-unit tracking. Assignments, statuses,
  the log and the average response time are computed in the browser, not precomputed.
- **Report New Incident** form -- dispatches instantly and highlights the route on the map.
- **Close a road (admin)** -> everything re-routes automatically.
- **Map**: scroll/drag/button zoom, search by place name, taluk filter, labels appear as you zoom, click a
  place to focus, click an assignment row to see its route.
- **Places Directory** table.
- Coordinates for the added places are **approximate** -- verify before any real use.

## Java program + MySQL (separate option)

The web app above stays standalone. In addition there is a **Java console program** with its own menu and a
**MySQL database**, which can also feed a second web page (`web/backend.html`, button *Java + MySQL Mode* on the dashboard).

### Java concepts used

| Topic | Where |
|-------|-------|
| Abstract class, inheritance, polymorphism | `ResponseUnit` -> `FireEngine`, `PoliceVehicle`, `Ambulance` (`describe()`, `getType()`) |
| Encapsulation, immutability | private fields + getters in `Location`, `Road`, `Incident`, `Assignment` |
| Interface | `Repository` (implemented by `JsonRepository` and `JdbcRepository`) |
| Comparable | `Incident.compareTo()` - 4-tier priority: critical infrastructure, severity, population exposure, report time |
| `PriorityQueue` (min-heap) | ranking incidents in `DispatchEngine`, Dijkstra frontier in `RoadGraph` |
| `HashMap` / `HashSet` | location lookup by id; unit equipment sets (`canHandle("FIRE")`); visited sets; route caches |
| `ArrayList`, `LinkedList`, `EnumMap` | roads, units, incidents; building routes; counting statuses |
| Graph + Dijkstra | adjacency list `HashMap<String, List<Edge>>`; closed roads are never added; O((V+E) log V) |
| JDBC | `JdbcRepository` (PreparedStatement batches, transactions) |

The Java engine produces the same dispatch results as `web/js/dispatch.js` for the seeded incidents (checked: same
units, routes, times and 4.5 min average).

### Run the console program

Needs JDK 11 or newer (`javac -version`). From the `sudar-dispatch` folder:

```
run.bat          (Windows)        ./run.sh          (Linux / macOS)
```

Menu: 1 places, 2 units, 3 roads (close/reopen), 4 report incident (auto-dispatch), 5 priority queue, 6 assignments + log,
7 shortest route, 8 OOP / data-structure demo, 9 MySQL menu, 10 start the web API. It runs without MySQL
(it reads `data/sudar-data.json`; changes stay in memory).

### MySQL setup

1. Install MySQL Server and download **Connector/J** (`mysql-connector-j-8.x.x.jar`) into `lib/`.
2. Edit `config.properties`: set `db.user`, `db.password` and `db.enabled=true`.
3. Start the program -> menu **9** -> **2** (create database and tables) -> **3** (import the data) -> **4** (use MySQL).
   (Or run `database/schema.sql` and `database/seed.sql` yourself in MySQL Workbench / the `mysql` client.)
4. From then on every new incident and every road closure is written to MySQL automatically, and the program starts from
   the database when `db.enabled=true` and the tables contain data.

Useful queries are listed at the end of `database/schema.sql`. If you change the data with `tools/build_data.py`,
run `python3 tools/make_seed_sql.py` to regenerate `database/seed.sql`.

### Web page connected to the Java backend

1. Start the Java web app: `run.bat api` / `./run.sh api` (or menu option 10 in the console program).
2. Open `http://localhost:8080/`, sign in, and click **Java + MySQL Mode**. The API base defaults to the same server.
3. Press **Connect**. The page shows the Java engine's map, log, ranked incidents and routes; *Report New Incident*
   and the administrator road buttons update the Java program (and MySQL when it is the data source).

The Java server also serves the frontend files, so the browser and API use the same origin. The standalone
`web/login.html` flow remains available when opened directly; its regular dashboard continues to use browser-local data.

**Not tested here:** the MySQL / JDBC part could not be run in the environment where this was written (no MySQL server or
driver available). The schema and seed data were loaded into a SQLite test database to check structure and row counts (not MySQL itself), the JDBC code compiles, and the
rest (Java engine, API, web page) was run end-to-end in JSON mode. Check the MySQL steps once on your machine.

## Honest disclaimers

This was built as an academic/portfolio prototype. It is **not** an
official Government of Tamil Nadu system, is not connected to any real
emergency service, and must never be used for actual dispatch decisions —
the footer on every dashboard page says the same. The emblem in the header
is a generic placeholder icon, not an official state or national emblem.

## Extending it

- Add your own places: append rows to `RAW` in `tools/build_data.py` (`name|TYPE|lat|lon|taluk`) and re-run it.
- Replace the demo `auth.js` with real server-side authentication before
  this touches any real data.
